## Publish a release

The intended public repository is `MeirinRuan/dsh-model-interruption-notifier`. Confirm the repository owner and public visibility before publishing. Keep only this independent project's files and history; exclude DSH profiles, Session logs, credentials, and the parent working tree. The [MIT license](../LICENSE) retains the inherited DeepSeek notice and credits this project's contributions.

Install dependencies, build, and test as described in the [development guide](guide.md#develop). `prepack` rebuilds the browser entry when pnpm creates a tarball. Use an existing output directory outside the checkout:

```text
pnpm pack --out <external-output-directory>/dsh-model-interruption-notifier.tgz
```

Inspect the archive before attaching it to a GitHub Release. It must contain `package/package.json`, the declared patch, `host.mjs`, `projection.mjs`, `lib/client.js`, locale files, icon, license, and documentation. Development dependencies, tests, personal settings, and Git metadata are excluded from the runtime package.

Create the public repository, push the reviewed commit, and add the `dsh-plugin` topic. Create a version tag and a matching GitHub Release, then attach the prebuilt archive with the stable asset name `dsh-model-interruption-notifier.tgz`. Future releases keep this asset name so that `releases/latest/download/` continues to work. A source-code ZIP generated by GitHub is not the prebuilt npm tarball.

The current compatibility declaration is the exact DSH version in `engines.dsh`. Expand it only after verifying the affected Host and Client services. No npm publication is required for the release-archive route; publishing to npm is optional, and its `repository` field must match the public GitHub repository.

## Request dsh-market listing

The market application is [dsh-market/dsh-market](https://github.com/dsh-market/dsh-market). Its **Submit your plugin** link points to the [awesome-dsh-plugin contribution guide](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin/blob/main/contributing.md). Submit the listing to that directory repository, not the market application's source repository.

The public guide requires real working code, a `package.json` with `dsh.bundle`, an actively maintained repository that is at least one day old, and the `dsh-plugin` topic. CI validates the submission, then a maintainer reads the target project. Passing CI does not itself approve a listing. Check the linked guide again before submitting because market rules can change.

Open a PR adding only `data/plugins/MeirinRuan__dsh-model-interruption-notifier.yml` to the directory repository. The [prepared entry](https://github.com/MeirinRuan/dsh-model-interruption-notifier/blob/main/market/MeirinRuan__dsh-model-interruption-notifier.yml) uses category `notify`, an accurate bilingual description, and this GitHub Release URL:

```text
https://github.com/MeirinRuan/dsh-model-interruption-notifier/releases/latest/download/dsh-model-interruption-notifier.tgz
```

Publish the repository and downloadable Release asset before submitting that entry. Do not hand-edit the directory's generated README, and do not add an `npm:` field to the YAML. The guide supports GitHub Release tarballs without npm publication. The optional listing icon must be a GitHub-hosted raster image; the plugin's SVG remains valid as its own package icon but is not supplied as a listing icon.

Maintainers can request changes in PR comments. Fix the same branch and respond once with the changes. The directory website rebuilds after merge; acceptance and propagation into the market are separate from creating a release.
